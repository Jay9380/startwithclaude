## A. `forbid-financial-advice.sh`가 막는 것과 놓치는 것 (`advice_hook_audit.sh`)

훅에 `drafts/x.md` Write 요청을 보내고 종료 코드로 판정했다(2 = 차단).

| 문장 | 결과 |
|---|---|
| 책 12.3.6의 예시 5개 (지금 사야 합니다 / 매수 적기 / 100% 수익 / 원금 손실 없음 / 마지막 기회) | **5/5 차단** |
| 바꿔 쓴 표현 6개 (지금 담아 두기 좋은 시점 / 저가 매수 구간 / 사 두셔도 좋습니다 / 손실 볼 일은 거의 없습니다 / 두 배는 간다고 봅니다 / `지 금 사 야`) | **0/6 차단** |
| 같은 줄에 부정어를 붙임 ("지금 사야 합니다. 망설일 이유가 **아닙니다**.") | **통과** |
| 정상 문장 ("이 리포트는 투자 권유가 아닙니다", "증권사는 매수 의견을 유지했다 [S3]") | 통과 (오탐 없음) |

- 정규식 21개 목록이라 **목록에 있는 표현만** 막는다. 7장(`--disallowedTools`)과 10장(`if: "Bash(rm *)"`)에서 본 문자열 매처의 성질 그대로다.
- 부정어 예외(`아닙니다|하지 않|금지|…`가 **같은 줄**에 있으면 통과)는 면책 문구의 오탐을 줄이려는 장치다. 하지만 부정어 하나를 덧붙이는 것만으로 금지 문장 전체가 빠져나간다.
- 그래서 이 하네스는 훅 다음에 **리뷰 에이전트**(content-editor: "투자 권유처럼 보이는 표현을 제거")를 둔다. 훅은 아는 표현을, 리뷰어는 의미를 본다. 두 겹이 다 필요하다는 근거가 위 표다.

## B. 같은 세션의 자기 검토 vs 새 세션의 검토 (`review_split.sh`, `review_fixture/`, `check_report.py`)

책 12.2.3은 앤트로픽 블로그("Out of the box, Claude is a poor QA agent… talk itself into deciding they weren't a big deal")를 인용하며 Evaluator를 분리하라고 한다.
가상 종목 데이터(`data.json`, 23영업일 종가와 출처 S1~S3)와 리뷰 기준 R1~R5(`spec.md`)로 쟀다. 리포트를 쓴 세션에 `--resume`으로 검토를 시킨 경우(self)와 새 세션(fresh)을 비교했다.

**첫 설계는 버렸다.** 생성 뒤 리포트 끝에 결함 4개를 덧붙이고 self 세션을 이어 가자 결함 4/4를 잡았다. 그중 1회는 `report.md`를 다시 읽지도 않고 "줄 16"을 짚었다.
`--resume`한 세션에는 **'파일이 바뀌었다'는 알림과 바뀐 줄이 자동으로 주입**된다. 심은 줄에 스포트라이트가 비친 셈이다. 같은 결함을 fresh는 3/4로 잡았다. R1(틀린 종가)을 놓친 것은 data.json을 열지 않았기 때문이다.
이 차이는 '자기 평가의 관대함'이 아니라 실험 장치가 만든 차이다.

**바꾼 설계.** 결함을 나중에 심지 않았다. 대신 생성 세션에 '검증 전 리서치 메모'(`research_note.md`)를 같이 줬다. 메모에는 틀린 종가 198,800, 출처 없는 점유율 주장, "지금이 담아 두기 좋은 시점", 날짜 05/28이 들어 있다. 생성 세션이 스스로 옮겨 쓰게 하려는 장치다.

| | 결과 (haiku 4회) |
|---|---|
| 리포트에 들어간 메모의 씨앗 | **0/4회** — 생성 세션이 매번 검증 안 된 메모를 걸러 냈다(spec: "다른 자료는 쓰지 않는다") |
| `check_report.py` 기계 판정 위반 | 4회 중 1회: 날짜 "2026년 4월 27일"(R4) |
| self 리뷰 | 그 R4를 잡음 1/1, 나머지 3회는 결론 문장 2개를 "출처 없음"(R2)으로 needs_fix |
| fresh 리뷰 | **self와 같은 판정** — R4 1/1, 같은 결론 문장 2개를 R2로 needs_fix |

- 이 작은 설정(haiku, 20줄 리포트, 규칙 5개)에서는 **self와 fresh의 차이가 없었다.** 책이 인용한 관대함은 재현되지 않았다. 더 긴 산출물, 더 모호한 기준, 더 긴 작업 세션에서 나타나는 현상일 수 있다.
- 오히려 두 리뷰어 모두 8회 전부 needs_fix를 냈다. "주가는 보합세를 보였습니다" 같은 해석 문장에 출처가 없다는 판정이다. 같은 장 NOTE의 다른 경고(OpenAI의 로포폴로: 리뷰어가 너무 엄격하면 Generator가 '괴롭힘'당한다)에 가까운 쪽이다. 리뷰 기준에 "해석 문장은 출처 대상이 아니다" 같은 경계를 적지 않으면 루프가 needs_fix를 반복할 수 있다. 책의 종료 조건(3라운드, 같은 지적 2연속이면 blocked)이 그래서 필요하다.
- 기계로 판정할 수 있는 규칙(R1 수치, R4 날짜, R5 결론)은 리뷰 에이전트보다 `check_report.py` 같은 스크립트가 싸고 확실하다. 책 12.3.9 '토큰 최적화'(본문 구조 검증을 파이썬으로)와 같은 결론이다.

## 하지 않은 것

- 하네스 실행(`/stock-goal`): yfinance·뉴스 RSS·코덱스 CLI 로그인·image_gen이 필요하다. 저자도 rate limit에 걸린 화면을 싣고 있다(12.3.9).
- 리뷰어 수(A-HMAD 1·3·5·7명): 비용 대비 측정 가치가 낮아 노트에서 수치만 정리했다.
