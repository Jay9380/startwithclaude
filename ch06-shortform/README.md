# 6장 · 숏폼 자동화 파이프라인 — 리뷰가 지적한 자막 결함을 테스트로 고정하기

책 6장은 마크다운 한 장(sample.md)을 9:16 숏폼(MP4)으로 만드는 MD2Short를 클로드 코드로 만든다
(ElevenLabs TTS+Scribe, OpenAI 대본, Remotion 렌더). docs/ 6개 문서(architecture, commit, memory, PRD, README, voice)를 먼저 세팅하고
`/deep-interview` → ralph로 30분 만에 첫 영상을 만든 뒤, **영상 리뷰(review.md) → "이걸 기반으로 개선해 줘"** 를 4번 반복한다.

**이 폴더는 영상을 만들지 않는다.** ElevenLabs·OpenAI 유료 API 키(카드 결제)가 필요하기 때문이다.
대신 책의 1차 리뷰가 지적한 두 결함을 **결정론적인 작은 코드로 재현하고, 테스트로 고정**했다.

| 리뷰 항목 (책 6.3.1) | 증상 (책) | 이 폴더 |
|---|---|---|
| C3 자막이 어절 중간에서 끊김 | `chunk_size=14` 글자 수 분할이 한국어 어절 경계를 무시 | `naive.py`가 재현, `caption.wrap_korean_caption()`이 수정 |
| H1 숫자가 한글 음차로만 노출 | "에스엔피 오백 종가가칠이삼영을" — TTS용 문장을 자막에도 씀 | `caption.split_display_and_speech()` — 자막은 원문, TTS만 읽기(6.3.4 2순위의 '표시 문자열/발음 문자열 분리') |

```bash
cd ch06-shortform
python3 -m unittest -v md2short_mini.test_caption     # 8개, 외부 패키지 없음
```

```text
naive : ['S&P 오백 종가 칠천이백', '삼십 기록했습니다.']          ← 숫자 하나가 두 줄로 갈리고, 숫자가 한글로만 보인다
fixed : [['S&P 500 종가', '7,230 기록했습니다.']]                ← 자막은 원문, 어절 경계에서만 줄바꿈
TTS   : S&P 오백 종가 칠천이백삼십 기록했습니다.                   ← 음성 입력만 한국어 읽기
```

숫자 읽기(`numbers.py`)는 책 6.3.4 리뷰의 표를 테스트로 고정했다 — `7,230 → 칠천이백삼십`, `0.94% → 영점구사 퍼센트`, `3.2% → 삼점이 퍼센트`, `18% → 십팔 퍼센트`.
범위 밖 숫자(8자리 이상)는 **추측해서 바꾸지 않고 원문 그대로** 둔다(실패 경로 테스트 포함).

### 테스트가 결함을 잡는지부터 확인했다

`NaiveVersionReproducesTheBug`는 '처음 버전이 정말 리뷰의 결함을 갖는가'를 확인하는 테스트다. 처음엔 `오라클이 미 국방부 AI …` 문장으로 썼는데,
**우연히 14자마다 공백에서 끊겨** 결함을 잡지 못했다(테스트 실패 = 테스트가 틀림). 숫자가 두 줄로 갈리는 문장으로 바꿨다.
결함 없는 코드에서만 통과하는 테스트는 아무것도 증명하지 못한다.

## 실험 — '리뷰 → 수정' 루프 (`experiments/run.sh`)

결함 있는 `naive.py`와 `numbers.py`만 주고(기준 구현과 테스트는 주지 않음) 클로드(haiku)에게 `caption.py`를 만들게 한 뒤, **숨겨 둔 테스트로 채점**했다.
함수 세 개의 이름·시그니처는 두 조건 모두 알려 줬다.

```bash
cd ch06-shortform/experiments
./run.sh 3 review   # review.md(책의 C3·H1 문장)를 주고 "반영해서 만들어 줘"
./run.sh 3 vague    # 리뷰 없이 "naive.py가 만드는 자막이 보기 안 좋아. 개선해 줘"
```

| 조건 | 결과 |
|---|---|
| 책의 리뷰(review.md)를 줌 | 3/3 테스트 통과 |
| 리뷰 없이 "보기 안 좋아" | **3/3 테스트 통과** |

리뷰가 없어도 통과했다. 이유는 **함수 인터페이스가 이미 리뷰의 내용을 담고 있었기 때문**이다 —
`split_display_and_speech(sentence) -> (자막 문자열, TTS 문자열)`, `make_screens … 화면당 최대 2줄`, `wrap_korean_caption(text, max_chars=14)`는
그 자체로 "자막과 음성을 분리하라, 2줄, 14자"라는 요구 사항이다. 리뷰의 역할은 **무엇이 문제인지 찾아 이름을 붙이는 것**이고,
이름(인터페이스)이 정해지면 구현은 쉬워진다. 책이 리뷰를 사람과 AI 둘에게 받아 합치고(6.3.1), 4차까지 반복하는 이유도
매 회차가 새로운 '이름 붙일 문제'(무음 구간 30%, 강조색 남용, 캐릭터 과사용…)를 찾는 일이기 때문이다.

측정 메모: 채점 줄의 `grep`이 실패 항목을 하나도 못 찾으면(=전부 통과) exit 1을 내서 `set -e`가 스크립트를 멈췄다. `|| true`로 고쳤다.
