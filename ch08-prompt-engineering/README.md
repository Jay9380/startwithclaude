# 8장 · 프롬프트 엔지니어링 — 예시는 '어휘'를 고정하고, 형식은 말로 못 박아야 고정된다

책 8장은 좋은 프롬프트의 여섯 요소(역할·지시·입력·배경·출력 형식·예시)와, 프롬프트를 강화하는 세 방법
(제로샷/원샷/퓨샷, 이터레이션, 오픈소스 프롬프트)을 claude.ai 웹에서 눈으로 확인한다.
이 폴더는 그 주장 중 **숫자로 잴 수 있는 네 가지**를 `claude -p`로 반복 실행해 센다.

claude.ai 웹과 조건을 비슷하게 하려고 클로드 코드의 시스템 프롬프트와 도구를 전부 뺐다
(`--system-prompt "You are a helpful assistant." --tools ""`). 모델은 haiku, Claude Code 2.1.286.

```bash
cd ch08-prompt-engineering/experiments
python3 prompt_lab.py all 3      # A~D 전부, 약 $0.9. 결과는 ../runs/lab-*.json (커밋하지 않음)
python3 prompt_lab.py A 3        # 하나만
```

## 결과 (2026-10-02)

### A. 제로샷 vs 원샷 — 리뷰 6개 × 3회 = 조건당 18회 (`exp_a`)

| 조건 | 라벨 한 단어만 | 평균 길이 | 쓰인 라벨 어휘 |
|---|---|---|---|
| 제로샷 (책 p.283) | 0/18 | 252자 | 부정적 6 · 긍정적 4 · 중립 4 · 혼합 3 · 긍정 1 |
| 원샷 (책 p.284, `좋아요 → Positive`) | **0/18** | 180자 | Negative 7 · Positive 6 · Neutral 3 · Mixed 2 |
| 원샷 + "라벨 한 단어만, 설명 금지" | **18/18** | 8자 | Negative 9 · Positive 6 · Neutral 3 |

- 책: "예시 하나로 출력 형식이 Positive/Negative 중 하나로 고정된다." 반만 맞다. 예시는 **어휘**(한글 5종 → 영문)를 고정했지만
  "**Negative** 이유는…" 식의 설명은 18번 모두 붙었다. 설명을 없앤 건 예시가 아니라 출력 형식 지시 한 줄이었다(8.1의 '5. 출력 형식').
- 웹 화면(그림 8-5)에서 한 단어만 나온 건 모델·UI 차이일 수 있다. 다른 모델에서 같은 결과가 나온다고 기대하지 말고 직접 세어 볼 것.

### B. 퓨샷과 다수 레이블 편향 — CS 문의 분류 (`exp_b`)

책 p.284의 예시 4개(균형)와, 같은 문의 4개의 우선순위를 **전부 '높음'으로 바꾼** 예시(책 NOTE의 majority label bias 조건)를 비교했다.
정답을 붙인 시험 문항 8개 × 3회 = 24회, 급한지 아닌지 단서가 없는 모호 문항 6개 × 3회 = 18회.

| 조건 | 형식 지킴 | 카테고리 | 우선순위 | 모호 문항 우선순위 |
|---|---|---|---|---|
| 제로샷 (지시만) | 0/24 | 23/24 | 19/24 | 보통 11 · 낮음 5 · **높음 2** |
| 퓨샷, 책의 균형 예시 | 23/24 | 24/24 | 22/24 | 낮음 11 · 보통 7 · 높음 0 |
| 퓨샷, 우선순위 전부 '높음' | 24/24 | 23/24 | 23/24 | 보통 11 · 낮음 7 · **높음 0** |

- 퓨샷의 효과는 **형식**에서 확실했다(0/24 → 23~24/24). 내용(카테고리)은 제로샷도 23/24로 이미 높았다.
- 다수 레이블 편향은 **이 과제·이 모델에서는 재현되지 않았다.** 예시가 전부 '높음'이어도 모호 문항을 '높음'으로 판정한 건 0회.
  문의 문장에 "급하진 않습니다", "지금 당장" 같은 의미 단서가 있어서 모델이 라벨 분포보다 의미를 따른 것으로 보인다.
  편향이 없다는 결론은 아니다 — 의미 단서가 약한 과제(임의 코드, 사내 등급)일수록 예시 분포를 따라갈 위험이 크다. 그런 과제라면 같은 방식으로 재 볼 것.

### C. 8.1.1 뉴스레터 프롬프트의 출력 조건 — 6회 × 버전 2개 = 12개 (`exp_c`)

책의 프롬프트(`newsletter_prompt.txt`)에 출력을 JSON으로 받는 줄 하나만 더했다.

| 조건 | 결과 |
|---|---|
| 본문 200자 이내 | 12/12 (85~154자) |
| CTA 1문장 | 12/12 |
| 버전 A에 '280', 버전 B에 '5분' | 6/6, 6/6 |

출력 형식에 적은 수치 조건은 전부 지켜졌다. 단 이건 "지켜졌는지"를 **코드가 셌기 때문에** 알 수 있는 사실이다 — 사람이 웹 화면에서 훑어보면 180자와 230자를 구별하지 못한다.

### D. 한글 vs 영문 프롬프트 토큰 (`exp_d`)

같은 뉴스레터 프롬프트를 영어로 옮긴 `newsletter_prompt_en.txt`와 입력 토큰을 비교했다(기준선 `hi` 392토큰을 뺀 값).

| | 글자 수 | 입력 토큰 |
|---|---|---|
| 한글 | 651자 | 549 |
| 영문 | 1,121자 | 313 |

한글이 **1.75배**. 책 NOTE의 "대략 1.5~3배" 범위 안이다. 글자 수는 영문이 1.7배 많은데 토큰은 한글이 많다 — 한글 한 글자가 토큰 하나에 가깝다.

## 하지 않은 것

- **이터레이션(8.2.2)의 '새 세션에서 비교하라'**: 측정 지표를 세우기 어려워 재지 않았다. `claude -p`는 호출마다 새 세션이라 이 실험 전체가 그 원칙을 따른다.
- **오픈소스 프롬프트(8.2.3, prompts.chat)**: 외부 웹 서비스라 실행하지 않았다. 책의 이미지 프롬프트가 claude.ai에서 SVG 그림이 되는 이유(클로드에는 이미지 생성 모델이 없다)는 노트에서 설명한다.
- 책 저자의 코딩 테스트 케이스 생성 프롬프트(p.289~291)는 저자의 사내 데이터(`data/problem/*.json`)가 있어야 돌아간다.
