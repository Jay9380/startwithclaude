## 실험 — 모호한 프롬프트 vs 구체적 프롬프트

```bash
cd ch01-vibe-coding/experiments
./run.sh 3        # 조건당 3회 (haiku, 약 $0.25). 생성물은 ../runs/*.html
./run.sh rescore  # 저장된 HTML만 다시 채점
```

| 조건 | 프롬프트 |
|---|---|
| 모호 | `할 일 앱 만들어 줘. index.html 한 파일로 만들어.` |
| 구체 | 할 일 관리 웹 앱을 index.html 한 파일(바닐라 JS)로 / 추가·완료 체크·삭제 / **완료된 항목은 목록 아래쪽으로 이동** / 로컬 스토리지에 저장 / 모바일 반응형 |

책의 구체적 프롬프트는 "React + TypeScript"인데, 한 파일로 실행·검사하려고 바닐라 JS로 바꿨다. "index.html 한 파일"은 두 조건에 똑같이 넣었다(채점을 위한 형식 조건).

**채점은 사람이 아니라 코드**가 한다 — `check_todo.js`가 jsdom으로 생성된 앱을 열어 실제로 입력·클릭한다.
추가 / 완료 체크 / 삭제 / 완료 항목이 아래로 가는가 / 새로고침(저장소를 넘겨 다시 부팅) 뒤 남는가 / viewport meta.

### 결과 (Claude Code 2.1.286, haiku, 2026-10-02)

| | 추가 | 완료 | 삭제 | 완료→아래 | 저장 | 모바일 | 합계 |
|---|---|---|---|---|---|---|---|
| 모호 ×3 | ✓✓✓ | ✓✓✓ | ✓✓✓ | **✗✗✗** | ✓✓✓ | ✓✓✓ | 5/6 ×3 |
| 구체 ×3 | ✓✓✓ | ✓✓✓ | ✓✓✓ | ✓✓✓ | ✓✓✓ | ✓✓✓ | 6/6 ×3 |

- **모호한 프롬프트도 '상식적 기본값'은 채운다.** 저장(localStorage)과 모바일 viewport는 말하지 않아도 세 번 다 들어갔다.
- **빠지는 것은 '나만의 요구사항'이다.** "완료 항목은 아래로"는 할 일 앱의 상식이 아니라 내 취향이다 — 말하지 않으면 한 번도 나오지 않았다.
  책의 "의도를 구체적으로"는 결국 **기본값과 다른 부분을 말하라**는 뜻이다.
- 비용은 거의 같았다(회당 $0.04 안팎). 구체적으로 쓰는 데 드는 건 토큰이 아니라 생각이다.

### 채점기를 두 번 고쳤다

1. **저장 검사 버그** — 정답 샘플 앱이 '저장 실패'로 나왔다. jsdom은 생성자 안에서 스크립트를 바로 실행하므로, 이전 저장소를 그 뒤에 넣으면 '새로고침'이 안 된다 → `beforeParse`에서 먼저 넣도록 수정. 저장 코드를 지운 앱은 저장만 실패하는 것도 확인했다.
2. **항목 찾기 버그** — 첫 채점에서 두 앱이 '완료·삭제 실패'로 나왔는데, 앱이 아니라 채점기가 `class="task-item"`을 못 찾은 것이었다 → "그 텍스트를 담고 체크박스나 버튼을 품은 가장 작은 요소"로 찾게 바꾸고 저장된 결과를 다시 채점.

채점기가 틀리면 결론이 뒤집힌다(첫 채점에서는 구체적 프롬프트 하나가 3/6이었다). **0점이나 이상치가 나오면 생성물보다 채점기를 먼저 의심한다.**

## Accept All 4가지 점검 — `accept-all-check/check.sh`

```bash
git diff | ./accept-all-check/check.sh     # 의심 항목이 있으면 exit 1
```

| # | 책의 점검 항목 | 스크립트가 찾는 것 |
|---|---|---|
| 1 | 인증/권한 — 접근 제어 코드가 빠지거나 약해지지 않았는지 | 지워진 줄의 auth·permission·requireLogin…, 추가된 줄에서 주석 처리된 것 |
| 2 | 외부 입력 처리 — 입력이 검증 없이 쿼리나 명령에 들어가지 않는지 | `SELECT … ${…}`, `"…" + x` 결합, `exec(… ${…})`, `shell=True` |
| 3 | API 키/비밀번호 — 하드코딩된 인증 정보 | `sk-…`, `AKIA…`, `ghp_…`, `password = "…"`(환경변수 읽기는 제외) |
| 4 | 새로운 의존성 — 낯선 패키지 | package.json·requirements·go.mod 등에 추가된 줄 |

픽스처 결과:

```text
$ ./check.sh < fixtures/risky.diff
[1 인증/권한] // const { requireLogin } = require("../auth"); …
[2 외부 입력] db.query(`SELECT * FROM users WHERE id = ${req.params.id}`);
[3 비밀]     const API_KEY = "sk-test-abc1234567890";
[4 새 의존성] "expresss-validator": "^1.0.0"     ← s가 셋인 유사 이름
→ 의심 항목 4개. Accept 전에 위 줄들을 직접 보라.   (exit 1)

$ ./check.sh < fixtures/safe.diff
4가지 점검: 의심 항목 없음                          (exit 0)
```

정규식 기반이라 거짓 양성·음성이 있다. **차단기가 아니라 '어디를 볼지' 알려 주는 체크리스트**다.
클로드 코드의 훅(10장)에 걸어 두면 커밋 전에 자동으로 돈다.
